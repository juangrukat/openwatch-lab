# O20 custom backgrounds: validated independent transfer

Documentation and synthetic fixture: CC0-1.0. Tested on itel ISW-O20, MOYOUNG-V2, software `O20-7LH2-2.1.12`, firmware `JLQFNS8KLX4.5`. This is a custom background, not a replacement firmware or arbitrary application installation.

**Result:** independently generated and uploaded a181960-byte test image. The watch returned the expected whole-object CRC, the commit was sent, and the user confirmed **“Yes, displayed correctly.”** No iPulse login, SDK, cloud or vendor asset was used by the uploader. These diagnostic results are not yet an upload button in app0.1.0.

## Image format

Use opaque RGB pixels in row-major order, top to bottom. Encode each pixel as RGB565 big-endian:

```python
high = (red & 0xF8) | (green >> 5)
low = ((green & 0x1C) << 3) | (blue >> 3)
```

Concatenate the original image (240×284×2=136320 bytes) and preview (140×163×2=45640 bytes), totaling181960 bytes. No PNG/JPEG header, extra image header or compression was used in the verified path. The preview in this test was generated by nearest-neighbor scaling. RGB test vectors: redF800, green07E0, blue001F, whiteFFFF.

Query39 supplies dimensions in extended layouts: uint16BE at37:39 original width,39:41 preview width,41:43 original height,43:45 preview height. These offsets count payload bytes, excluding the five-byte command header. Validate dimensions before writing. Other model/firmware combinations may require a different format; do not generalize the separate JL707/multiple-photo path to this O20.

## Wire protocol

Ordinary command serviceFEEA: FEE2 write, FEE3 notify. Image bytes go on **FEE6**. Expand short UUIDs as `0000xxxx-0000-1000-8000-00805f9b34fb`.

Commands are framed `FE EA (20 | lengthHighNibble) lengthLow command payload`; length includes five header bytes. Reassemble fragmented notifications. The observed O20 replies use protocolV2 (20/30 length header), which uses raw FEE6 image chunks without the older FE/FFFF chunk headers or per-chunk CRC fields.

1. Subscribe to FEE3 and validate device/software identity. Snapshot selected face and layout. Confirm the object fits the maximum reported by5A/08. Avoid overlapping image transfers or ordinary query operations.
2. Prepare the complete encoded image and compute unreflected CRC16/CCITT, polynomial1021, initFEEA, xorout0. Python `binascii.crc_hqx(image, 0xFEEA)` matches the SDK algorithm. Vector ASCII123456789 givesB798 with this seed.
3. Begin: command6E with image length as **uint32BE**. Test frame: `FE EA 20 09 6E 00 02 C6 C8`.
4. Honor **BA subtype01 negotiation**. Payload `01 00 28` announces logical chunk size **uint16LE10240**. This event preceded the first chunk request on the tested O20. Do not confuse this size with the ATT write limit. Other sizes must be validated and bounded.
5. Command6E with exactly two payload bytes requests a **zero-based uint16BE index**. Slice `image[index*N : min((index+1)*N, len(image))]`, with negotiatedN10240 here.
6. Write that slice, raw, on FEE6. Split it into ordered ATT writes limited to the characteristic capacity and the SDK ceiling256, rounded down to a multiple of4. The tested host reported512-byte capacity; each full logical chunk was therefore40×256-byte writes. The test inserted10ms between ATT writes. Do not interleave chunks or append a chunk index/header/CRC on this V2 path.
7. Repeat requested chunks on duplicate indices; bound retries and enforce timeouts. Reject malformed/out-of-range requests. The first attempt ignored BA01 and sent256 bytes for a10240-byte chunk; the watch repeatedly requested index0. The experiment cancelled after11 repeats and restored the prior face. Honor negotiation to avoid reproducing this failure.
8. A four-byte command6E payload is terminal: `[index:BE16, wholeObjectCRC:BE16]`. The test received `FF FF 74 FF`. Confirm all chunks were sent and the CRC matches the complete encoded image. Do not treat the two-byte indexFFFF as an ordinary chunk request.
9. On a match, commit with command6E payload`00 00 00 00`. On error/timeout/cancellation, send6E payload`FF FF FF FF` while connected, and restore the recorded built-in selection if appropriate. Never report a cancelled upload as successful.
10. Verify actual rendering. A successful checksum proves byte integrity, not correct image encoding or orientation.

The test transferred18 logical chunks:17×10240 plus a final7880 bytes. Selected-face query29 remained01 after commit, and the background appeared on that face. The layout39 hash area stayed zero even after the successful image; it is not a reliable success indicator for this transfer path.

## Memory result

5A/08 returns a **512000-byte maximum transferable object**, not total RAM, total flash or available user storage. B4/10 remains only partially decoded. The JL707-specific memory query did not answer in earlier O20 tests; its decoder cannot be applied here. The5A/08 limit and rawB4/10 reply were unchanged when reread after this successful upload. This image establishes enough allocated background storage for this object, but does not measure the watch's overall memory.
